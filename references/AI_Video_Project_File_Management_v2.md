# AI 视频项目文件管理

> 本文是[《项目初始化文档》](Project_Initialization.md)的 **AI 视频专题**，适用于文生视频、图生视频、视频转视频，以及 AI 动画、实拍、合成混合制作。本文只补充视频项目的专业目录、命名、流转与追溯规则；通用项目管理要求仍以主文档为准。
>
> **核心原则：以镜头追溯生成过程，以资产管理跨镜头复用，以工程管理后期制作，以交付版本冻结最终成果。**

一个项目可以只有一个镜头，也可以由多个场次、镜头构成。目录按需创建，不要求空目录齐全；但一旦创建，就遵守统一的文件职责和命名规则。所有路径均相对项目根目录，Markdown 链接须按**链接所在文件**计算相对路径。

---

## 一、需要管理哪些文件

下面列出一部视频从策划到发布可能用到的文件。**“正式位置”指该类文件的唯一维护位置**；其他地方只建立路径、链接或记录，不反复复制。

| 类别 | 主要文件 | 正式位置 | 备注 |
| --- | --- | --- | --- |
| 项目策划 | 策划案、项目简介、目标受众、制作规格、排期、预算（如需） | `work/planning/brief/`；进度在 `management/` | 策划内容与项目管理记录分开 |
| 文学与声音文本 | 故事大纲、剧本、对白稿、旁白稿、歌词、配音台本 | `work/planning/script/` | 保留明确版本；对白段落可分配稳定 ID |
| 镜头设计 | 分镜表、分镜画稿、镜头清单、预演/动态分镜 | `work/planning/storyboard/`、`work/planning/animatic/` | 分镜意图与实际剪辑顺序分开记录 |
| 视觉制作规范 | 画幅与安全区、色彩、视觉风格、镜头语言等文字规则 | `work/planning/standards/` | 规范正文链接到实际采用的资产版本 |
| 视觉参考资产 | 项目采用的视觉参考图、色彩方案图、构图示意图 | `work/assets/style/`；外部原始参考放 `inputs/references/` | 文件可供跨镜头复用，文字要求由规范维护 |
| 角色设计 | 角色概念、定稿、三视图、表情库、服装/动作设定 | `work/assets/characters/CH001/` 等 | 同角色保持稳定 ID；三视图包括正、侧、背 |
| 场景设定 | 场景概念图、结构/布局、时间或天气变体、背景图 | `work/assets/locations/LOC001/` 等 | 剧本“场次”和可复用“地点资产”不是同一编号 |
| 道具设定 | 道具概念图、结构图、材质/状态变体 | `work/assets/props/PR001/` 等 | 可复用道具集中保存 |
| 原始输入 | 客户文件、参考图片、外采音视频、实拍原片、原始录音 | `inputs/` | 尽量保留原始文件、来源与授权信息 |
| 镜头关键帧 | 首帧、中间关键帧、尾帧及本镜头专用输入 | `work/shots/S010/frames/` | 共用角色/场景图不在此复制一份 |
| 单镜头视频 | 生成候选、选用源片、修复/补帧/超分后的入剪版本 | `work/shots/S010/generations/`、`edit-media/` | 原始生成与加工成片必须区分 |
| 声音素材 | 对白录音、配音、旁白、环境声、拟音、音效、音乐、分轨 | 原始采集在 `inputs/audio/`；制作资产在 `work/audio/` | 原始录音和剪修/设计后的版本分开 |
| 后期工程 | 剪辑工程、合成工程、调色工程、混音工程 | `work/post/` 对应子目录 | 工程依赖的媒体须可定位和重连 |
| 后期产物 | 时间线交换文件、合成渲染、调色输出、混音版本 | `work/post/` 对应子目录 | 工作产物不是正式交付版 |
| 字幕文件 | 中文字幕、外语字幕、双语字幕、硬字幕所用源文件 | `work/post/subtitles/` | 正式发布所需字幕另进入对应交付包 |
| 审片资料 | 审片视频、意见、问题清单、修订结果 | 视频在 `work/post/review/`；意见在 `management/reviews/` | 意见必须绑定审片轮次和时间码 |
| 正式交付 | 成片、独立字幕、最终混音、封面、缩略图、交付清单 | `deliverables/release-vNNN/` | 每次交付冻结一套，不直接覆盖旧版 |
| 历史归档 | 被取代但须保留的方案、旧交付快照、归档清单 | `archive/` | 不随意搬动仍被工程引用的文件 |

**补充说明：** 配音选角/试音、歌曲工程、音频降噪、音效设计、转场、特效工程、LUT、代理文件、发布文案等也可能出现，但不需要为所有项目强制建目录。依其性质分别归入 `work/audio/`、`work/post/`、`cache/` 和 `deliverables/`。

### 目录使用边界

1. **`inputs/` 保存原始事实。** 收到的文件、摄像机原片及原始录音尽量保持原状；如必须重命名，记录原文件名及来源。不要直接在此覆盖修图、降噪或剪切。
2. **`work/planning/standards/` 维护文字规范，`work/assets/` 保存可复用资产文件。** 角色、场景和道具的图像探索版也可放在对应资产目录。资产登记表指向当前批准版，来源、生成过程和版本变更写在 `management/asset-logs/`。角色外观等需要执行的文字约束写入策划规范，并引用对应设计图。
3. **`work/shots/` 保存镜头特有的生成链。** 本镜头关键帧、实际提示词、原始候选、处理后视频在镜头下集中管理。引用角色定稿时使用路径链接，不复制资产。
4. **`work/audio/` 管理可以反复编辑/复用的声音内容，`work/post/audio/` 管理整片声音后期。** 例如，对白原始录音在 `inputs/audio/recordings/`，清理对白在 `work/audio/dialogue/`，混音工程在 `work/post/audio/projects/`，最终独立音轨在交付包中。
5. **`deliverables/` 只接收验收后的复制件和清单。** 制作母版仍在工作路径中，发布冻结包不被后续修改覆盖。
6. **`cache/` 可删不等于随时可删。** 只有确认可从保留的源文件、插件和设置重新生成，且不被工程硬引用后，才可清理。

### 规范怎样引用资产

小项目可以把画幅、色彩、镜头语言等写在一份 `work/planning/standards/film-spec-v001.md` 里。内容较多时，可拆成 `film-framing-spec-v001.md`、`film-color-spec-v001.md` 等，由项目入口指向当前采用版。规范正文写可执行的要求，如画幅、有效画面范围、工作色彩空间和输出色彩空间。视觉参考、色板和构图示意作为资产随文引用。以下是从 `work/planning/standards/` 内的规范文档写出的相对链接。

| 规范中的内容 | 引用示例 |
| --- | --- |
| 画幅与安全区规则 | `[安全区示意图](../../assets/style/film-safe-area-v001.png)` |
| 色彩与用色规则 | `[色彩方案图](../../assets/style/film-color-palette-v002.png)` |
| 角色造型约束 | `[角色设计图](../../assets/characters/CH001/design/CH001-design-master-v003.png)` |

## 三、统一文件命名规范

文件名要让人和 AI **不打开文件也能初步识别对象、内容和版本**。目录承担分类，文件名承担唯一辨识；不把所有信息堆进文件名。

### 3.1 基本规则

- **目录名**使用英文小写 `kebab-case`，如 `edit-media`。固定的资产/镜头 ID 目录允许大写，如 `CH001`、`S010`。
- **自制工作文件名**优先使用 ASCII 字母、数字、连字符 `-`、小数点 `.`；ID 大写，语义词小写。如 `CH001-turnaround-front-v002.png`。不使用空格、中文标点、`最终`、`新版`、`final2`、`修改后`。
- **基本格式：** `<对象ID或项目简称>-<内容类型>[-<描述/用途>]-vNNN.<扩展名>`。`v001` 起步，三位补零；仅内容被修订才增加版本号。
- **原始 AI 视频候选例外：** `<镜头ID>-video-gNNN-cNN.<扩展名>`；`g` 表示第几次生成任务，`c` 表示该次任务的第几个候选，**不使用** `v` 代替生成次数。
- **录音素材例外：** 录音以 `takeNNN` 区分不同条次；剪修后的音频再使用 `vNNN`。
- **审片例外：** `rNNN` 表示审片轮次，不代表镜头或工程版本。审片反馈与被审的 `rNNN` 一一对应。
- **源文件扩展名**保留实际格式，例如 `.png`、`.exr`、`.wav`、`.mp4`、`.mov`、`.md`、`.csv`、`.srt`、`.ass`、`.drp`、`.prproj`、`.rpp`。不为了统一名称擅自转码。
- 命名后避免随意改名，尤其是已经被剪辑、合成、混音工程引用的媒体。迁移或更名必须同步更新引用并重新打开工程验证。

### 3.2 编号与后缀字典

| 标记 | 示例 | 含义 | 规则 |
| --- | --- | --- | --- |
| `S` | `S010` | 镜头 ID | 创建独立镜头时分配；即使剪辑调序也不变 |
| `SCN` | `SCN003` | 剧本场次 ID | 用于故事结构，不等同于场景资产 |
| `CH` | `CH001` | 角色资产 ID | 同一角色的设定、三视图、表情共用此 ID |
| `LOC` | `LOC001` | 可复用场景/地点资产 ID | 同一地点可被多个场次、镜头引用 |
| `PR` | `PR001` | 道具资产 ID | 同一道具的不同状态复用此 ID |
| `DLG` | `DLG012` | 一条对白/配音条目 ID | 文本与录音互相引用；如需精细对白管理时启用 |
| `SFX` / `AMB` / `MUS` | `SFX003` | 音效/环境声/音乐条目 ID | 为有复用价值的声音资产分配 |
| `vNNN` | `v003` | 某个文件内容的第三版 | 不代表第三次 AI 生成；旧版不覆盖 |
| `gNNN` | `g004` | 该镜头第四次生成任务 | 每次实际重新提交生成任务增加编号 |
| `cNN` | `c02` | 同一生成任务的候选 02 | 同次返回多个结果时区分 |
| `takeNNN` | `take003` | 第三次录音条次 | 原始录音条次不随剪修更改 |
| `rNNN` | `r002` | 第二轮审片 | 对应确定的审片视频和反馈 |
| `NNN`（关键帧顺序） | `000`、`010`、`999` | 首帧、中间关键帧、尾帧的排序位置 | 紧跟 `kf-`，按文件名升序排列 |
| `tNNNpN` | `t002p0` | 镜头内相对时间 2 秒 | 用于中间关键帧。时间基准写入镜头卡 |

编号不复用，不因删除镜头而回填。可按 `S010`、`S020`、`S030` 留空号方便插入；新增镜头也可以使用新的连续编号。镜头拆分或合并时给新镜头分配新 ID，并在变更记录中建立旧新映射。

### 3.4 关键帧按画面顺序排序

格式为 `<镜头ID>-kf-<三位顺序号>-<start|mid|end>[-<镜头内时间>]-vNNN.<扩展名>`。顺序号放在帧类型前。按文件名升序排列时，每个镜头的首帧在最上方，尾帧在最下方，中间关键帧按画面顺序居中。

```text
S010-kf-000-start-v002.png
S010-kf-010-mid-t002p0-v001.png
S010-kf-020-mid-t003p0-v001.png
S010-kf-999-end-v001.png
```

首、尾固定使用 `000` 和 `999`。中间帧按镜头内时间顺序分配 `010`、`020`、`030` 等。两张之间新增一帧时，可用 `015` 这样的空号。顺序号表示排列位置，`t` 后的值表示镜头内时间，`v` 表示同一关键帧的修订版本。已有文件采用旧命名时，可以在下次修订中启用新格式。需要批量改名时，先记录旧名和新名的映射，再同步更新镜头卡、镜头表、提示词中的文件引用、生成日志和工程引用，并重新打开相关工程确认素材可读取。

**版本与命名举例：** 修改首帧得到 `S010-kf-000-start-v003.png`，并据此重新生成，则新任务命名 `S010-video-g005-c01.mp4`。如果仅对 `g004-c02` 做超分而没有重新生成，得到的应是 `S010-video-edit-v004.mov`，**不是** `g005`。

## 四、开工时先建立的索引

不需要立刻创建整棵目录树；但至少建立下面四个入口，以免后来出现“文件很多，却不知道哪版在用”的问题。

### 4.1 `README.md`：项目入口

至少写明项目简介、当前阶段、主要交付对象和下一项任务。链接到当前策划案、剧本、分镜表、镜头表、`work/planning/standards/` 下采用的规范、主要工程与最新交付清单。画幅、色彩、音频等规则的详细要求在规范文档维护。

### 4.2 `management/shot-tracker.csv`：镜头状态

推荐字段如下；可先在 Markdown 中维护小表，镜头数多再换为 CSV/表格。

| 镜头 ID | 对应场次 | 目标/计划时长 | 当前状态 | 当前入剪文件 | 使用的关键帧/资产 | 待修问题/下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| `S010` | `SCN001` | 人物回头，3.5 秒 | 已入剪 | `work/shots/S010/edit-media/S010-video-edit-v002.mov` | `CH001`、`LOC001`、`S010-kf-000-start-v002.png` | 核对与下一镜视线衔接 |
| `S020` | `SCN001` | 门被推开，4 秒 | 待选片 | — | `LOC001`、`PR001` | 对比候选的推门方向 |

建议状态：`待设计 → 待生成 → 待选片 → 已入剪 → 已锁定`。发生返工时按实际工作退回前面的状态。**状态只在索引记录，不写入文件名。** “已锁定”只表示当前阶段确认通过；重新开启须记原因。

### 4.3 `management/asset-register.csv`：资产总索引

至少包括：`asset_id`、`name`（人类可读名称）、`type`（角色/场景/道具/声音/风格）、`approved_path`（当前批准版相对路径）、`status`、`source_or_rights`、`used_by`、`updated_at`。角色的各项三视图与表情可在 `management/asset-logs/CH001.md` 单独列出，总表登记主设计的批准路径即可。

当角色主设定、服装或场景概念更新时，按 `used_by` 检查受影响镜头。**不要用覆盖同名文件的方式“悄悄更新定稿”。**

### 4.4 `management/decision-log.md` 与 `delivery-log.md`

前者登记重大版本选择、镜头拆合、设计锁定、规格变更；后者记录每次交付的版本、日期、文件、工作工程、是否发布及发布地址。小项目可以精简，但要有可追溯入口。

## 五、镜头与生成过程的标准管理

单镜头 `work/shots/S010/` 使用固定结构：

| 位置 | 维护内容 | 关键约束 |
| --- | --- | --- |
| `shot.md` | 画面目标、场次、时长、引用资产、输入、当前入剪版、注意事项 | 记录当前有效状态，不代替历史日志 |
| `frames/` | 首帧、中间帧、尾帧及该镜头专用输入图 | 关键帧各自保存为单张完整图片，按 `kf-000`、`kf-010` 等顺序号排列 |
| `prompts/` | 按 `gNNN` 存实际提交提示词 | 记录对图像引用的真实文件路径/版本 |
| `generations/` | 模型原始输出的各候选视频 | 原件保留，不原位覆盖、修复或改时长 |
| `edit-media/` | 补帧、超分、画面修复、转码等处理版 | 必须能追溯源候选、处理方法和参数 |
| `generation-log.md` | 每轮任务、输入、工具设置、候选评价与选片决策 | 至少完整记录入选候选及后续仍可能依赖的尝试 |

`generation-log.md` 的推荐模板：

```markdown
## S010-g004

- 日期：YYYY-MM-DD
- 平台/模型/版本：
- 任务 ID（可取得时）：
- 模式：文生视频 / 图生视频 / 视频转视频 / 混合
- 目标镜头与预计时长：S010，3.5 秒
- 实际输入：
  - 首帧：work/shots/S010/frames/S010-kf-000-start-v002.png
  - 中间帧（若实际使用）：work/shots/S010/frames/S010-kf-010-mid-t002p0-v001.png
  - 尾帧：work/shots/S010/frames/S010-kf-999-end-v001.png
  - 角色参考：work/assets/characters/CH001/design/CH001-design-master-v003.png
- 提示词：work/shots/S010/prompts/S010-prompt-g004.md
- 参数：画幅 / 分辨率 / 帧率 / 时长 / seed / 工作流版本（按实际可取得项）
- 输出：
  - work/shots/S010/generations/S010-video-g004-c01.mp4
  - work/shots/S010/generations/S010-video-g004-c02.mp4
- 选择：采用 c02；理由是动作与视线更连贯
- 待修：手部局部修复
- 处理后入剪版：work/shots/S010/edit-media/S010-video-edit-v002.mov
- 处理链：g004-c02 → 修复手部 → 超分 → edit-v002（必要时链接到参数/工作流）
```

**注意：** 以上路径都相对项目根目录；如果直接写成 Markdown 链接，应根据 `generation-log.md` 的实际位置改成相对链接。提示词中若使用“首帧”“参考角色”等简称，日志必须明确每个简称对应哪一个真实输入文件。

文生视频无需强制创建 `frames/`；图生视频按实际输入保留关键帧；视频转视频要记录源视频及使用片段的源时间码。一段源视频被多个镜头使用，**仅保留一份原始文件**，分别在各镜头的 `shot.md` 中写入源路径和源入出点。

## 六、角色、场景、道具如何管理

所有可跨镜头复用的设计都遵循同一流程：**探索 → 对比 → 选定 → 批准 → 被镜头引用 → 修订影响检查**。

- **角色 `CH001`：** `design/` 存角色概念与当前正式设计；`turnaround/` 存正面、侧面、背面；`expressions/` 存不同情绪的独立图片；`variants/` 存服装与其他明确派生形态。`management/asset-logs/CH001.md` 记录批准情况、原始参考和生成过程。需要各镜头遵循的造型约束写在 `work/planning/standards/`，并链接到对应的角色设计图。
- **场景 `LOC001`：** `concept/` 存氛围与美术设定；`layout/` 存空间布局或机位参考；`variants/` 存昼夜、季节、天气、破损/完好等变化。分镜里 `SCN003` 可以引用 `LOC001`，但两种编号不能混用。
- **道具 `PR001`：** `design/` 存正式外形/结构；`variants/` 存打开、闭合、损坏、发光等状态。若某件道具仅在 S010 出现且不需要复用，可作为镜头专用参考保存在 `S010/frames/`，不必强制升级为共享资产。

共享资产发生版本更改时：新增版本文件 → 在资产日志登记变化 → 更新资产登记表批准路径 → 找出引用镜头 → 决定重生成、修复或保留旧版。**不能因为资产已经更新就自动替换历史镜头输入。**

## 七、声音、字幕与后期工程如何管理

### 7.1 声音的三层结构

| 层次 | 举例 | 放在哪里 |
| --- | --- | --- |
| 原始来源 | 演员录音 `DLG012-CH001-take003.wav`、外购音效、授权音乐 | `inputs/audio/recordings/`、`inputs/audio/sfx/`、`inputs/audio/music/` |
| 制作资产 | 去噪/剪接对白、编辑音效、场景环境声、配乐版本、音乐分轨 | `work/audio/dialogue/`、`sfx/`、`ambience/`、`music/` 等 |
| 整片后期 | 混音工程、时间线配音/配乐/音效分轨、审片混音 | `work/post/audio/projects/`、`stems/`、`mixdowns/` |

对白、旁白、歌词或配音台本先在 `work/planning/script/` 统一维护。录音与文本通过 `DLG` 编号或行号对齐；原始录音要能查到人物、条次和来源。混音工程需要与剪辑工程对应，记录参考画面版本、采样率、声道、响度目标、插件/音色依赖和最终混音版。

音乐如果是自行创作，作曲/歌声制作源工程存 `work/audio/music/projects/`，音乐输出存 `renders/`，可复用音乐分轨存 `stems/`；进入整片混音后的对白/音乐/音效总分轨则在 `work/post/audio/stems/`，不要与作曲分轨混淆。

### 7.2 剪辑、合成、调色与字幕

- **剪辑：** 可编辑工程保存在 `work/post/edit/projects/`；导出的 `.xml`、`.edl`、`.aaf` 等放 `timelines/`；工作检查视频放 `renders/`。镜头表中的“当前入剪素材”与工程引用应保持一致。
- **合成与调色：** 相关工程、必要素材、渲染和所使用的 LUT 在 `work/post/vfx/`、`work/post/color/` 内按软件和实际需要细分。若合成只为单镜头制作，也应从镜头卡链接到对应工程。
- **混音：** 原始对白、音效、音乐不得直接被导出的整体混音覆盖；保留能重建混音的源工程和关键分轨。
- **字幕：** `work/post/subtitles/` 保存当前字幕工作母版（`.srt`、`.ass` 等）及对应语言版本。字幕时间码与实际锁定剪辑核对；正式交付时，把确切版本复制到 `deliverables/release-vNNN/subtitles/`，并在 `manifest.md` 中登记。

工程保存“版本”并不意味着媒体都复制一遍。尽可能维持项目根目录下的相对路径；对必须使用绝对路径的软件，交付或归档前执行一次离线重连检查。保存软件版本、插件依赖、外部字体、音色、LUT，以及必要时的工程导出/备份。

## 八、从立项到结项的文件流转

| 阶段 | 主要动作 | 必须可定位的文件与记录 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| **01 立项** | 明确目标、范围、规格、交付对象与版本方案 | `README.md`、策划案、`work/planning/standards/`、项目决策 | 目标和验收标准明确 |
| **02 剧本与分镜** | 大纲、剧本、场次、分镜表、必要预演；分配稳定编号 | `planning/script/`、`storyboard/`、镜头表 | 分镜画面、计划时长、依赖关系可执行 |
| **03 资产设计** | 风格、角色三视图/表情库、场景、道具；审批基准版 | `work/assets/`、`management/asset-logs/`、资产总索引 | 关键角色/场景/道具已明确引用版本 |
| **04 单镜头制作** | 准备关键帧、实际提示词、生成与比较候选 | `shots/Sxxx/` 的帧、日志和原始候选 | 入选候选可追溯、可衔接 |
| **05 音频制作** | 录音、清理、音效、音乐、分轨及初混 | `inputs/audio/`、`work/audio/` | 声音素材有来源且可用于时间线 |
| **06 剪辑与后期** | 入剪、修复、合成、调色、混音、字幕 | `post/` 工程、处理版和字幕工作文件 | 全片可播放、工程依赖有效 |
| **07 审片与修订** | 发布固定审片轮次，整理意见，回修受影响对象 | `post/review/`、`management/reviews/`、变更日志 | 关键问题关闭并复验 |
| **08 正式交付** | 输出各成片版本、独立字幕/音轨/封面并验收 | `deliverables/release-vNNN/manifest.md` | 文件规格和内容均符合交付要求 |
| **09 结项归档** | 冻结工程、保留重要原始输入与依赖、删除可重建缓存 | 交付记录、归档清单、可打开的工程 | 从交付版可以回溯到工程和使用素材 |

上表说明**数据流向，不规定严格线性流程**。例如声音可以和镜头生成并行；角色设计更新可能让项目从剪辑阶段返回资产设计与镜头制作。每次返工只更新受影响的文件和索引，不必重建整个目录。

## 九、审片与交付版本

审片和交付是两个不同层级，不可混用。

**审片流程：**

1. 从已保存的剪辑工程生成 `work/post/review/film-review-r003.mp4`。
2. 在 `management/reviews/film-review-r003-notes.md` 中逐条记录：`审片轮次 | 全片时间码 | 镜头ID | 问题 | 处理方案 | 负责人（如有） | 复验状态`。
3. 返工后新增对应镜头素材、字幕、混音或工程的版本；再次导出新的 `rNNN` 审片版。
4. “审核通过”只对应某个确定版本及审片范围，不代表后续文件可以静默替换。

**交付流程：**

每次正式交付创建独立的 `deliverables/release-vNNN/`。其中 `manifest.md` 至少包含：

```markdown
# 交付清单：release-v001

- 交付日期：YYYY-MM-DD
- 交付用途/平台：
- 基准剪辑工程：work/post/edit/projects/film-edit-v005.drp
- 基准混音工程/混音文件：
- 基准字幕工作文件：
- 成片：video/film-main-v001.mp4
- 外挂字幕：subtitles/film-subtitles-zh-Hans-v001.srt
- 成片规格：分辨率 / 画幅 / 帧率 / 编码 / 时长 / 音频 / 色彩
- 校验：文件存在、可播放、音画同步、字幕核对、缺帧/黑帧检查
- 发布状态及链接（如有）：
- 备注：本交付版本变更摘要
```

交付清单内的相对链接或路径，应以 `manifest.md` 所在目录为准。上面“基准工程”示例是**项目根目录相对路径的登记值**，如改为可点击链接，应换算到正确层级。对外发布的文件使用确定版本，后续更新创建 `release-v002/`，**不原地覆盖 `release-v001/`**。

## 十、Git、大文件、备份与权限

- Git 可管理 `.md`、`.csv`、提示词、配置、脚本、小型工程描述文件与 `.gitignore`；视频、长音频、高分辨率图像和大型二进制工程不宜直接加入普通 Git 历史。使用 Git LFS 或独立素材存储时，应有可恢复的存储位置和索引。
- **默认不向公开仓库推送视频项目全量素材。** 外部素材可能有版权限制，配音录音/未公开剧情/客户资料可能不宜公开。若要公开项目仓库，先定义允许公开的文件清单、忽略规则和授权范围，再执行推送。
- 至少备份：策划和剧本定稿、当前批准的角色/场景/道具、已采用的关键帧与原始候选、生成日志、实际入剪媒体、剪辑/合成/混音工程、字幕源文件、正式交付版与交付清单。
- 缓存、代理和可重建的中间渲染可以单独管理，但删除前要确认工程可重连、生成过程可重现。云端 AI 服务产生的原始结果可能无法再次下载，不能默认视为“可重建缓存”。
- 外部素材建议另存 `source`、`license`、`usage_scope` 等记录，尤其是音乐、音效、字体、参考图与实拍肖像，避免交付时遗漏授权条件。

## 十一、人类与 AI 交接模板

交接任务应包含六项：**目标对象、当前基准、允许修改、禁止修改、输出位置、验收条件**。必要时再补充模型/工具、关联镜头和受影响范围。

```markdown
## 任务：修复 S010 的手部变形

- 目标对象：S010
- 当前基准：work/shots/S010/edit-media/S010-video-edit-v002.mov
- 参考输入：work/shots/S010/frames/S010-kf-000-start-v002.png
- 问题定位：work/post/review/film-review-r003.mp4，00:12–00:14
- 允许修改：手部局部形状、必要的局部遮挡
- 禁止修改：角色外观、镜头构图、画面总时长和原始候选
- 输出：work/shots/S010/edit-media/S010-video-edit-v003.mov
- 必须记录：本次输出来自哪个原始候选及处理方法
- 验收：手部正常，前后动作连续，时间线无黑帧/音画错位
- 完成后：更新 S010/shot.md、shot-tracker.csv，并验证剪辑工程引用
```

AI 操作前优先读取 `README.md` → 当前任务相关索引 → 对应资产/镜头卡 → 实际输入。只修改任务范围内的文件；不要因“看起来是旧文件”就批量删除、重命名或覆盖。

## 十二、最终检查清单

### 立项和资产

- [ ] 项目入口可找到当前采用的策划案、剧本、分镜表、规格和当前任务。
- [ ] 文字规范在 `work/planning/standards/`，可打开其中引用的资产版本。资产的来源和版本记录在 `management/`。
- [ ] 分镜中每个独立镜头有稳定 ID，场次和可复用场景资产未混用编号。
- [ ] 角色定稿、三视图、表情库、场景概念和道具设定（项目需要的部分）均有明确位置与批准版本。
- [ ] 共享资产更新后，可以找出依赖它的镜头。

### 镜头和声音

- [ ] 关键帧按名称升序呈现首、中、尾，镜头卡和生成日志指向实际使用的文件。
- [ ] 关键帧、生成提示词、原始候选与处理后入剪版可以逐层追溯。
- [ ] 原始录音、处理版对白、音效、音乐、音乐分轨、整片混音工程各有明确存放位置。
- [ ] 当前入剪文件与镜头表一致；镜头替换后已检查切点、时长、衔接和音画同步。
- [ ] 剪辑、合成、调色、混音工程均可打开，并能找到必需的源文件和插件依赖。

### 审片、交付和归档

- [ ] 审片意见能定位到具体 `rNNN`、全片时间码、镜头 ID 和处理结果。
- [ ] 字幕语言、时间码、画面、音频及交付规格已检查。
- [ ] 每个交付包包含正式成片和按需配套文件，并有 `manifest.md` 对应基准工程与版本。
- [ ] 历史交付版不被覆盖；正式项目文件有备份；清理缓存前已验证不会断链。

**最小实施方式：** 单镜头练习可只创建 `README.md`、`work/shots/S010/`、所需 `work/post/` 和 `deliverables/release-v001/`；出现角色、场景、道具跨镜头复用后再建 `work/assets/`。多镜头、多人或多轮交付项目则增加 `management/` 中的索引和审片记录。无论规模大小，都应保持相同的 **ID、版本、来源和交付** 规则。
